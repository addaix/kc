# Research detail: agent memory, provenance and abstention

Supporting detail for [../research.md](../research.md). Claims are graded strong / moderate / weak / contested.

## Agent memory, provenance and abstention

**Verification status of this section.** All three underlying topic reviews (agent memory, provenance standards, abstention/calibration) were compiled *without* an adversarial verification pass. Findings drawn from primary standards text, peer-reviewed benchmarks and specifications read in full are reported at face value; findings that rest on a single unreplicated preprint, on a vendor report, or on a reviewer's own negative search result are flagged inline as **[unverified pass]** and should be treated as leads to test rather than premises to build on. Evidence grades used throughout: **strong** (peer-reviewed or primary-standard, methodology public, ideally corroborated), **moderate** (single credible study, or credible-but-interested source with disclosed methodology), **weak** (single-author/unreplicated preprint, small n, or absence-of-evidence), **contested** (the literature actively disagrees).

### Agent memory is a research area with one clean result and a great deal of unrefereed noise

The single most design-relevant number in the memory literature is not a system comparison at all — it is an ablation *inside one model*. On LongMemEval-S (~115k-token histories), GPT-4o scores 0.870 when handed only the oracle evidence sessions and 0.606 when handed the full history: a 30.3% relative drop. Llama-3.1-70B drops 55.1% (0.744 → 0.334) and Phi-3-128k 45.9% [1]. The model is not compute-limited, it is distraction-limited. **Strong.** This is the number that justifies building a selection layer at all, and it does so with no vendor system in the loop; it also sets the ceiling any retrieval design is chasing, which is why an oracle-evidence upper bound belongs in the evaluation harness as a first-class figure. An independent replication on the same benchmark by Chroma reports ~80% on focused ~300-token prompts against ~55% on the full 113k-token history for Claude Sonnet 4, and ~75% vs ~50% for GPT-4.1, across 18 models from four vendors [2]. **Moderate** — the source is a vector-database company whose product benefits from the conclusion, though the methodology and tasks are fully disclosed.

Whether long context obviates retrieval turns entirely on whether the corpus is *bounded*, not on how large the window is. For corpora that fit, long context beats RAG on average [3], a 4K model with simple retrieval matches a 16K fine-tuned long-context model at far lower compute [4], and long-context models rival specialised retrieval pipelines on LOFT [5]. **Strong**, from three independent studies — and none of those settings is agent memory, where history is unbounded and grows monotonically. The engineering rule that follows is unusually crisp: do not build a memory system for a bounded knowledge base that fits the window; stuff the window.

What the long-context benchmarks actually show, as distinct from what their headline numbers are used to claim:

| Benchmark | Finding | What it kills | Grade |
|---|---|---|---|
| HELMET [6] | Most long-context models achieve near-perfect needle-in-a-haystack while showing large gaps on real tasks; HELMET's own task categories correlate poorly with each other | NIAH as a proxy for usable context; rank transfer across task types | strong |
| RULER [7] | Only about half of models claiming ≥32K windows maintain satisfactory performance at 32K | The advertised window as a budgetable capacity | strong |
| NoLiMa [8] | Remove lexical overlap between question and needle and 11 of 13 models claiming 128K+ fall below half their short-context baseline at 32K (GPT-4o 99.3% → 69.7%) | Any retrieval evaluation whose items share vocabulary with the stored text | strong |
| LongPiBench [9] | Across five commercial and six open-source models, "most current models are robust against the 'lost in the middle' issue"; the surviving bias is driven by *distance between* relevant pieces, not absolute position | The 2023 mitigation ("put important things at the edges") as a current design rule | moderate, **contested** |
| Liu et al. [10] | The original U-shaped positional degradation, real for its model generation | — | strong for 2023 models |

Lost-in-the-middle is the clearest case where a widely-repeated design rule has outlived its evidence, but it is genuinely **contested**: mechanistic work continues to model the U-shape as architecturally real, and the ACL 2025 Findings result is one benchmark. The safe reading is that the effect that survives is co-location — facts that must be reasoned over jointly should be adjacent in the assembled context — while absolute head/tail placement is no longer the lever it was. A second, awkward finding from the same Chroma report is that all 18 models performed *better* on shuffled, incoherent haystacks than on logically structured ones [2]; that is the opposite of the common instinct to reconstruct document order when assembling context, and it is a vendor result on an unverified pass, so it is a hypothesis to test rather than a rule to adopt.

### Benchmark validity: who built the benchmark, and did anyone else run it

The founding architecture of this area has never been refereed. MemGPT — the origin of the virtual-context-management framing, ~1,195 citations — remains an arXiv preprint (v2, Feb 2024) with no peer-reviewed venue [11]. Its evaluation introduced Deep Memory Retrieval, a benchmark defined by the same team, now effectively saturated: a competing vendor reports 94.8% against MemGPT's 93.4%, a 1.4-point margin [12]. **Strong** (primary sources: arXiv listing, venue record, the competitor's own paper). The idea — OS-style paging of context — is worth borrowing freely; the empirical claim has no independent refereeing behind it.

LOCOMO, the benchmark most memory systems report on, *is* peer-reviewed (ACL 2024) and reasonably constructed — machine-human pipeline, persona and temporal-event-graph grounded, human-verified [13]. Two properties nonetheless limit its use as a superiority test: its dialogues are LLM-generated and then LLM-judged by overlapping model families, and the published version's own description of the data differs from the preprint's (600 turns / 16K tokens / up to 32 sessions vs ~300 turns / 9K tokens / up to 35 sessions), so papers citing "LOCOMO's size" do not agree with one another. **Strong** (both primary sources read directly).

Reported LOCOMO numbers are not comparable across papers, and the spread is enormous. Independent evaluations place memory systems at 21–54% where system papers self-report 68–99% on the same benchmark; six unreported protocol variables — ingestion granularity, raw-text preservation, retrieval budget, retrieval modality, rubric audit, judge choice — move rankings, and in one documented case a convincing win vanished once retrieval budget was equalised (the winner had been consuming 2.6M characters of retrieved context per query) [14][15][16]. **Moderate** — two independent preprints plus a cost-focused third-party comparison, converging with the wide numeric spread visible across the ~25 LOCOMO-reporting preprints the source review surveyed. **[unverified pass]** on the survey's base-rate claim specifically.

| Source | Ordering on LOCOMO | Interest | Grade |
|---|---|---|---|
| Independent reproducible testbed [16] | mem0, plain RAG and full-context cluster at 77–81%; Graphiti (Zep) and cognee reach 55–56%; plain RAG matches the top cluster at **8.4× lower total cost of ownership** than mem0; gap attributed to retrieval *incompleteness*, not reasoning | none — measures accuracy, latency, CPU, RAM, disk, network for all arms | moderate |
| Mem0 vendor paper [17] | Mem0 ahead of a MemGPT baseline | vendor evaluating its own product with LLM-as-judge | weak as a comparison |
| Zep vendor paper [12] | Zep ahead of MemGPT on a MemGPT-defined benchmark | vendor | weak as a comparison |
| Letta engineering blog [18] | States it could not reproduce Mem0's MemGPT baseline (Mem0 did not respond to requests for clarification or supply the modified implementation) and measures 74.0% where Mem0 reported 68.5% | vendor, but the load-bearing content is a first-party statement that its own system's baseline was misreported | moderate for the reproduction failure only |

Two measurement artefacts are larger than any architecture in this literature. Strict token-F1 and LLM-as-judge differ by **27.5 points on identical model outputs**; and changing only *which memory form receives retrieval credit* (raw stored form, source dialogue turn, or canonical representation) changes nDCG on 83.4–94.0% of shared queries without rerunning retrieval at all [19][20]. **Moderate** — two single-author rescoring audits, checkable in method but unreplicated **[unverified pass]**. Meanwhile the judge that nearly every memory claim rests on has documented position, verbosity and self-enhancement biases, and its famous ~80% human-agreement figure was measured on *chatbot response preference*, not factual memory recall [21]. **Strong** for the biases; the absence of any judge-human agreement study on an agent-memory benchmark is the source review's own negative search result — **weak, and explicitly an absence of evidence**.

The practical consequence is a reading prior rather than a ranking: assume a published win is a protocol artefact until retrieval budget, judge and baseline configuration are disclosed *and* equalised, and treat an internal A/B against a plain-RAG baseline as worth more than any published comparison.

### What the memory evidence supports about design

Cheap, measured, and inside a peer-reviewed benchmark's own ablations: index at **round** rather than session granularity, and store a **fact-augmented key** — extracted user facts concatenated with the verbatim value at index time — for an average +9.4% recall@k and +5.4% final accuracy across models [1]. **Moderate**, and the only concrete v1 retrieval recipe in this area measured against a proper baseline.

Structure buys retrieval cost, not answer quality. A systematic study of filesystem-organised agent memory found organised stores roughly halve retrieval cost on large material while "no agent we measure converts organization itself into better answers", with organisation eroding as the store grows for all but the strongest management agent — and changing the tool set alone reshaped the store as strongly as swapping the model [22]. **Moderate** (preprint, credible group). This converges with three independent lines: HippoRAG 2's authors note earlier structured-RAG approaches drop "considerably below standard RAG" on basic factual memory [23]; Microsoft's GraphRAG headline is LLM-judged comprehensiveness and diversity win-rates on global sensemaking, reporting no retrieval-accuracy comparison [24]; a systematic RAG-vs-GraphRAG evaluation finds neither dominates and hybrids win [25]; and the independent LOCOMO testbed ranks both graph systems last [16]. **Strong** as a convergent negative for the accuracy case. Structure remains defensible on cost, latency and auditability. A related measurement discipline follows from the observation that retrieval recall and end-answer accuracy diverge — MemConflict reports "answer correctness often diverging from memory retrieval and ranking" across six long-term memory systems [26] (**weak**, preprint, **[unverified pass]**) — so instrument the two halves separately: did the right evidence get retrieved, and given the right evidence was the answer right.

Three findings that are load-bearing for a knowledge-context system but rest on thin evidence, all **[unverified pass]**: recency was the *worst* retention signal in the one head-to-head comparison found (0.368 gold-evidence retention against 0.770 for a learned multi-factor model, 0.657 uniform, 0.518 best single factor; 479 cases, paired bootstrap CIs above zero) with reliability and user-relevance dominating the learned weights [27], corroborated only by a second preprint observing time-driven decay collapsing to near-zero weights over 100 rounds [28] — **weak**; belief-based (Bayesian) conflict resolution gives minimal advantage over last-write-wins on ordinary conversational recall because standard benchmarks contain almost no differently-reliable conflicting evidence, while grounding trust in *source provenance* resists volumetric poisoning where grounding it in the statement's textual confidence does not [19] — **weak**, though it reports against its own thesis; and memory-substrate rankings do not transfer across operating regimes, with broad retrieval improving long-context factual QA while *degrading* sequential decision-making [29] — **moderate** for the substrate study, **weak** for the observed inversion of architecture rankings between three and nine weeks of history (n=6 users, p=0.031) [30].

Two findings deserve to survive into the design regardless of the memory-system question. First, retrieval can be net-negative: on RAGuard, whose misleading documents are naturally occurring (drawn from Reddit) rather than synthetically injected, *every* tested LLM-powered RAG system performed worse than its own zero-shot no-retrieval baseline while human annotators did better, and the authors argue that benchmarks using gold documents or synthetic noise systematically overestimate RAG performance [31]. **Strong** (NeurIPS 2025). A no-retrieval arm belongs in every evaluation. Second, **memory consolidation strips authorisation**: "authority collapse", where converting interaction history into reusable facts preserves the claim but erases the source constraints governing its authorised use, was found in 48 of 49 configurations across seven consolidators and seven backbones, and persisting predicted authority labels through consolidation drove unauthorised-action rates from 16.9% to 0.0% with no loss of task performance [32]. **Moderate** (broad configuration coverage, clean intervention, not peer-reviewed or replicated). This is the index-time half of permission enforcement that query-time filtering silently depends on: any summarisation step that does not propagate provenance and authority is a security defect, not a lossy convenience. Independently, no current method achieves utility, access control and reliable forgetting simultaneously in a multi-principal shared store — and long-context prompting often scores *best* on governance, at high token cost, while retrieval and external-memory methods leak unauthorised and explicitly deleted content [33]. **Moderate**.

Finally, a reason to store observations rather than conclusions: multi-turn interaction degrades performance by 39% on average across six generation tasks versus fully-specified single-turn, decomposing into a small aptitude drop plus a large rise in unreliability, because models commit early and cannot recover [34]. **Moderate** (widely cited preprint, not peer-reviewed). A memory layer that persists early conclusions converts a recoverable in-context mistake into a durable stored one.

### Provenance: what W3C PROV and Web Annotation specify, and what they cost

PROV is explicitly a three-tier vocabulary designed to be subsetted, and the tiers differ wildly in size: Starting Point is 3 classes + 10 properties, Expanded 7 + 16, Qualified 20 + 20; the spec itself says users "may only need to use parts of the entire ontology" [35], and PROV-DM likewise separates core structures (Entity/Activity, Derivation, Agent) from extended ones (Bundles, Alternates, Collections) [36]. **Strong** (Recommendation text). "Adopt PROV" is therefore not one decision but at least three.

Does anyone use the full model? W3C's own implementation census is the direct answer: of 66 reported implementations, **only three both produced and consumed all PROV-DM constructs**, and only three validators implemented all of PROV-CONSTRAINTS; over 40 touched PROV-O, 12 implemented PROV-N, and 13 of 66 entries were vocabulary *extensions* [37]. **Strong** (primary census). The cost is structural and countable: the unqualified form (`:e1 prov:wasGeneratedBy :a1`) is 2 triples, the qualified form adds 3 triples plus a new node before any domain property attaches, and roughly half of PROV-O (20 of ~30 classes, 20 of ~46 properties) exists solely to support that pattern [35]. **Strong.** Any knowledge-context system needs per-edge attributes — confidence, role, timestamp, extraction method — so this is the pattern it would be paying for, at ~2.5× graph blow-up per annotated edge. Emitting PROV from application code was itself hard enough to motivate a standardised templating layer that splits provenance topology from runtime values, with bindings measured at ~40% of the size of the provenance they expand into [38]. **Moderate** (IEEE TSE, abstract).

The four largest real-world provenance deployments do not use PROV-O as a wire format:

| Deployment | Model actually used | Relation to PROV | Grade |
|---|---|---|---|
| C2PA content credentials [39] | CBOR/COSE/JUMBF manifests: claims, assertions, ingredients | A direct token count over the 2.1 spec finds **zero** occurrences of "PROV-O", "prov-dm", "W3C PROV" or "RDF"; it normatively references Dublin Core (dc:format in claims), schema.org, XMP, Exif, IPTC | strong |
| OpenLineage [40] | Own Job / Run / Dataset + facets JSON model | none | strong |
| HL7 FHIR [41] | Bespoke `Provenance` resource "based on the W3C Provenance specification" | Covers only PROV's Generation-of-Entity; Usage and all other Activity are routed to `AuditEvent` | strong |
| RO-Crate [42] | schema.org in JSON-LD | A full W3C PROV bundle is permitted only as an attached side-file, because full PROV is "at a different granularity level that might become overwhelming if represented directly" | strong |

Where PROV *is* deployed as PROV it is scientific-workflow provenance, always with domain extensions layered on (CWLProv, wfprov/wfdesc, ProvONE) [43] — a good fit for an ingestion pipeline's execution trace, a poor fit for editorial provenance of knowledge claims. **Moderate.** The defensible synthesis: PROV's durable value is its *conceptual* vocabulary (entity/activity/agent; generation, usage, derivation, attribution, revision). Name fields after PROV concepts so the mapping is documentable; store records.

Vocabulary size and vocabulary *use* are almost unrelated, and this is measured at web scale. schema.org V30.0 has 823 types and 1,529 properties [44]; Web Data Commons' October 2024 corpus (2.39B pages parsed, 16.5M domains carrying structured data, 74.0B triples) shows head classes on millions of pay-level domains — SearchAction 6.76M, Person 5.57M, Organization 4.32M — against tail classes on hundreds or dozens: ClaimReview 343, Park 337, TelevisionStation 89, RiverBodyOfWater 25 [45]. Four to five orders of magnitude, inside one vocabulary. **Strong.** Adding terms demonstrably does not produce data in them: Paulheim's diachronic analysis found domains "for which no deployed data can be found at all, such as the medical domain, where a larger vocabulary was bulk-integrated", an official extension mechanism "only rarely used, without a measurable impact", and `schema:sameAs` — the one property that would make the corpus linkable — "deployed by less than 0.02% of all Microdata providers", while deprecations propagate quickly [46]. **Strong** (web-scale corpus, read in full). Dublin Core repeats the pattern: OAI-PMH §3.4 normatively mandates unqualified 15-element Dublin Core as the interoperability floor rather than DCMI Terms' 55+ properties [47][48], and across 35 harvested collections only `title` and `identifier` appear in 100% of repositories, with `creator` in 39% of *records* and `rights` in 52% [49]. **Strong.** The engineering consequence is blunt: never let ranking, permission enforcement or conflict resolution depend on a field that is 40% populated — the rule will silently apply to a minority of the corpus. Crosswalks compound this: remapping native records to Dublin Core measurably changes description/format/subject/type counts, with multi-valued content collapsed into single elements with ad-hoc delimiters, and published crosswalks "do not always account for semantic values of elements" [49] — so retain the raw source record beside the normalised one, or you can never distinguish "the source did not say" from "our mapping dropped it".

What *did* drive schema.org adoption, empirically, was not extensibility: direct business incentive (better search listings produced stricter schema conformance), ready-to-adapt documentation examples, implementation inside widely deployed CMSs (producing large-scale usage "sometimes even unconscious to the website owner" *and* greater homogeneity), and a standard flexible enough to legalise systematic violations after observing them [46]. **Moderate.** Deployed-markup error rates are correspondingly low — 5.6% of documents using undefined types and 9.7% undefined properties, against 38.8% and 72.4% in Linked Open Data [50] (**moderate**, seen via citation only). Auto-emission at ingestion is what produces both the volume and the consistency.

The W3C Web Annotation Data Model is the better-specified primitive for the citation anchor itself. An Annotation must have exactly one IRI and one or more targets; a target may be a `SpecificResource` bearing `FragmentSelector`, `TextQuoteSelector` (exact + prefix + suffix), `TextPositionSelector` (start/end), `RangeSelector`, `CSSSelector`, `XPathSelector` or `SVGSelector`, and "A Selector MAY be refinedBy 1 or more other Selectors"; it carries `creator`/`created` *and* `generator`/`generated` — the human-versus-machine distinction an AI system needs — plus a `motivation` from a 13-value extensible list [51]. **Strong** (Recommendation, read in full). It is genuinely deployed, and deployments both constrain and extend it: IIIF Presentation API 3.0 restricts `motivation` to painting/supplementing and deviates on `label` [52], while a live Hypothesis API payload carries **three co-registered selectors for one target** — a RangeSelector (XPath containers + offsets), a TextPositionSelector (char 68381–68472) and a TextQuoteSelector with prefix and suffix context [53]. **Strong** for the observation; note that whether multi-selector anchoring measurably improves re-anchoring survival under drift is **unmeasured** — the practice is deployed, the rationale is obvious, and no published evaluation quantifies it.

Content drift, not link rot, is the failure that matters. Klein et al. analysed 3.5M+ articles and 1M+ web references and found "one out of five STM articles suffering from reference rot", rising to seven in ten among articles that actually contain web references; the decisive detail is that "the number of articles infected with reference rot is very close to the number of articles that lack appropriate Mementos", with only 22% of references having an archive snapshot within 30 days of publication and 0.3% within one day [54]. **Strong** (PLOS ONE). A 200 response is not evidence the content still supports the claim, and no third-party archive can be assumed to exist: capture and content-hash the cited extract at index time and store the retrieval datetime. If cached context is versioned, RFC 7089 (Memento) is the solved interface shape — Original Resource / Memento / TimeGate / TimeMap, negotiated via `Accept-Datetime` [55]. **Strong.**

For conflict, Wikidata's deployed model is a three-part design worth copying wholesale: three ranks (preferred / normal / deprecated) where deprecation is *retention with a marker*, kept explicitly to prevent accidental re-addition and to document how knowledge evolved; rank orthogonal to sourcing — "References merely state where a data value comes from; ranks indicate what data value is considered the most correct"; and queries returning best rank silently while the conflict stays inspectable [56]. **Strong** (primary documentation of a large production knowledge base). Conflating "which value wins" with "where the value came from" into one field is the standard design error. Note also that RDF has no native way to attach provenance to an individual statement; the clean primitive (`rdf:reifies`, triple terms, motivated in the spec by wanting to "make statements about unasserted statements") is still only at Candidate Recommendation as of April 2026 [57][58] — **moderate**, and a concrete argument for a record store over a triple store when per-claim provenance and per-claim conflict are the central requirement.

### Are cited answers faithful to their citations? No, and it replicates

Two independent human audits of production systems, two years apart, agree:

| Audit | Systems | Finding | Grade |
|---|---|---|---|
| Liu, Zhang & Liang [59] | Bing Chat, NeevaAI, perplexity.ai, YouChat | "a mere 51.5% of generated sentences are fully supported by citations and only 74.5% of citations support their associated sentence" | strong (Findings of EMNLP 2023, human annotation) |
| Venkit et al. [60] | You.com, Bing Copilot, Perplexity; 303 queries + 21-participant usability study | ~25–30% of statements unsupported by listed sources; roughly two-thirds of citations point to a supporting source for You.com/Bing and **under half** for Perplexity; Bing lists 36% uncited sources; all engines include ≥30% of sources supporting no unique information; citation thoroughness 20–25% | strong for the automated audit, moderate for the usability findings (preprint) |
| RAGTruth [61] | ~18,000 naturally generated RAG responses, word-level annotation | Exists precisely because "despite the integration of RAG, LLMs may still present unsupported or contradictory claims to the retrieved contents"; a fine-tuned small model matches prompt-based GPT-4 at detecting them | moderate (ACL 2024, abstract) |

Mis-citation is a *distinct* failure from ungroundedness: "even when there exists a source that supports a statement, all engines still frequently cite a different incorrect source" [60]. Users do not compensate — one participant: "I mean it's just like you see a citation, you assume it's a valid source... I'll just see that there is a source. That's it. I don't verify it." **Moderate.** If only one check is built, build the per-citation one.

Attribution as formally defined is explicitly *not* a truth claim. AIS asks whether a hearer would judge "According to P, s" to hold, "where s is interpreted relative to time t"; its authors state that source characteristics "such as source quality... can be measured using complementary metrics that are out of scope in this work", and that "AIS does not set policy about where model output should fall" [62]. **Strong.** A system can be 100% attributable and 100% wrong; rendering "cited" as "verified" is the most consequential elision in this area. Because attribution is indexed to time t, every attribution assertion needs a timestamp and re-verification when the source changes.

Automatic attribution evaluation is a usable *aggregate* signal and an unreliable per-example gate. ALCE's TRUE-NLI-based citation metrics agree with human judgement at Cohen's κ = 0.698 for citation recall and only 0.525 for precision (85.1% / 77.6% accuracy) [63]; AttributionBench reports a fine-tuned GPT-3.5 reaching only ~80% macro-F1 on the binary supported/unsupported formulation, with most errors on nuanced information and on the information gap between model and annotator [64]; SummEdits finds most LLMs "close to random chance" on inconsistency detection, with GPT-4 8% below estimated human performance [65]. **Strong** as a convergent limit. There is also no metric for the middle state: ALCE's authors state outright that "there is no existing model that can judge whether a citation partially supports a claim" and that prompting for the three-way judgement "yields poor results" [63], and a dedicated comparative study of full/partial/no-support metrics concluded "no single metric consistently excels across all evaluations" [66]. **Moderate.** A schema with only cited/not-cited collapses a three-state fact and systematically penalises correct multi-source synthesis.

Citation-quality metrics have a degenerate optimum. On ASQA, emitting the top-1 retrieved passage verbatim scores citation recall 99.4 and precision 99.4 against ChatGPT's 73.6 / 63.0 — while MAUVE fluency collapses from 66.6 to 20.8 and answer correctness drops from 40.4 to 35.1 [63]. **Strong** (published ablation). Citation quality reported alone is maximised by copying; it must always be paired with a measure that copying destroys.

Two constructive results. Architecturally, "Attribute First, then Generate" restructures generation into content selection → sentence planning → sequential generation so that the selected source segments *are* the attributions, reporting more concise citations, maintained or improved generation quality and attribution accuracy, and significantly reduced human fact-verification time [67]. **Moderate** (ACL 2024, abstract) — but it is the highest-leverage decision available, because it eliminates mis-citation by construction rather than auditing for it. Evaluation-wise, the method with the strongest validation path is nugget-based: TREC's AutoNuggetizer shows "strong agreement at the run level between scores derived from fully automatic nugget evaluation and human-based variants", while being explicit that "further research is necessary... particularly in establishing robust per-topic agreement" [68]; the companion SIGIR perspective pairs nuggets for completeness with separate citation checks for verifiability [69]. **Moderate**, with a hard boundary: the validated unit is the *run*, not the answer. Nugget scores compare versions of a system; they do not gate a response. Human judgement does not rescue per-answer gating either — AIS inter-annotator agreement runs from Krippendorff's α = 0.91 on conversational QA down to 0.60 (Wizard-of-Wikipedia) and 0.46 (CNN/DM summarization), which the authors attribute to how much context an annotator must read, at 73–308 seconds per item after training (687s at pilot) [62]. **Strong.** Cite small units, and price human review at 1–5 minutes per claim before promising it at volume. The vocabulary itself is fragmented — a systematic analysis of 134 papers found 300 evaluation metrics across seven dimensions [70] — so definitions have to be written down rather than assumed.

### Abstention and calibration: selective prediction, risk-coverage, and where confidence comes from

The classical framing is the one to adopt as vocabulary: Chow's optimum error-reject trade-off [71], El-Yaniv & Wiener's selective classification with explicit risk-coverage characterisations [72], and Geifman & El-Yaniv's deep-network selective classifier guaranteeing a target risk at chosen coverage [73], with a TACL survey organising LLM abstention along query / model / human-values axes [74]. **Strong.** Using *coverage*, *selective risk*, *risk-coverage curve* and *coverage at target risk* makes an evaluation section directly comparable to published baselines.

Two methodological results should be adopted before any gate is built. First, the standard evaluation practice for failure detection is broken: a holistic reformulation measuring risk-coverage (AURC) across the full spectrum of shifts rather than AUROC on curated splits "reveals a simple softmax response baseline as the overall best performing method", which the authors describe as underlining drastic shortcomings of current evaluation [75]. **Strong** (ICLR 2023 oral). Report AURC and coverage-at-target-risk, and always include max-softmax or max-retrieval-score as the baseline any proposed gate must beat. Second, plug-in ECE estimators are biased and under-report miscalibration, and popular recalibration methods (Platt, temperature scaling) are "less calibrated than reported", with current techniques unable to estimate how miscalibrated they are [76]. **Strong** (NeurIPS 2019 spotlight). Do not ship plug-in ECE as a calibration KPI.

Abstention is not free. Selective classification **magnifies group disparities**: across five vision and NLP datasets, abstention improved average accuracy while widening accuracy gaps between groups, and increasing abstention *decreased* accuracy on some groups outright, with the condition characterised by full-coverage accuracy and a left-log-concavity property of the margin distribution [77]. **Strong** (ICLR 2021, with a proof for symmetric margins). Risk-coverage must be reported per segment — tenant, topic, language, document age, source — not only in aggregate. The symmetric failure is over-abstention: XSTest systematically documents exaggerated refusal of clearly safe prompts that merely resemble unsafe ones [78], while refusal-aware instruction tuning shows the capability generalises as a meta-skill and improves calibration [79]. **Moderate** both. Every abstention-policy change needs a false-abstention suite shipped alongside the hallucination suite.

Abstention capability also does not transfer. A top SQuAD 2.0-trained system "drops considerably in out-of-domain scenarios", failing even on the simpler non-competitive IDK questions where the context contains no entity of the expected answer type [80]; SQuAD 2.0 contains learnable artifacts that MRC models demonstrably exploit [81]; and under domain shift, softmax-based abstention fares poorly because models are overconfident out of distribution, whereas a calibrator trained to predict model error — benefiting from exposure to out-of-domain data *even from a different domain than the test set* — answers 56% of questions at 80% accuracy against 48% for raw probabilities [82]. **Strong** (three peer-reviewed studies with explicit OOD splits). There is no off-the-shelf abstention capability to buy; there is a labelled in-corpus set to build, plus a held-out OOD slice that need not match production exactly.

### Do retrieval-side signals predict answerability better than model-side confidence?

This is the section's central design question, and the honest answer is: **the useful axis is supervision, not side.**

| Predictor family | Reported strength | Grade |
|---|---|---|
| Pre-retrieval QPP (IDF, SCQ, VAR) | correlation ~0–0.1 with actual RAG gain [83] | moderate |
| Unsupervised post-retrieval score-distribution predictors (NQC / score separability [84], WIG, SMV) | ~0.1–0.2 [83]; QPP-only prediction of answer quality on NQ/BM25 Spearman ρ ≈ 0.245, rising to 0.282 with reader-side context perplexity [85] | moderate |
| Reference-list predictor | 0.25–0.30 [83] | moderate |
| Model-side post-generation uncertainty | 0.35–0.55 [83] | moderate |
| Supervised cross-encoder over question + context | 0.45–0.49 [83] | moderate |
| Learned passage-utility predictor (one small-model pass per passage, no generation) | AUROC 0.78–0.80 average across 4 QA models × 6 datasets, vs 0.70–0.78 for p(True), 0.63–0.73 for semantic entropy, 0.56–0.73 for answer perplexity; on deliberately unanswerable RefuNQ 0.78–0.81 vs 0.60–0.68 for p(True) [86] | moderate (TMLR 2025, DeLong tests) |
| Joint (question + context + both candidate answers) | 0.71–0.79 on NQ-Open, 0.87–0.89 on TriviaQA [83] | moderate |

Three conclusions follow, and none of them is "retrieval beats the model". **Raw retrieval statistics are weak** — a cosine threshold, a score gap or a score standard deviation will not carry an answerability decision. **A learned retrieval-side sufficiency signal is strong, and its margin is largest exactly in the low-coverage regime** you care about, because the model "confidently generates a response and also fails at assessing it" precisely where it lacks the knowledge [86]. And **the best gate is a combiner over both families**: combining a sufficient-context autorater label with model self-rated confidence in a simple logistic regression improved the selective-accuracy/coverage trade-off by >10% (Gemma 27B on HotpotQA, high-accuracy region) and >5% (Gemini 1.5 Pro at ~70% coverage) over confidence alone — while abstaining on the sufficient-context signal *alone lowers overall performance*, because models answer a substantial fraction correctly even with insufficient context [87]. **Moderate** (ICLR 2025, 3 datasets × 5 model families). The gain disappears when overall accuracy is very low.

The confound is worth stating explicitly, because it is the main reason not to over-read the table: every strong "retrieval-side" result is a model *trained on end-task correctness*, while the model-side baselines it beats (perplexity, entropy, p(True)) are unsupervised. Nobody has run the matched-supervision ablation. **Unresolved.** Two secondary asymmetries cut in opposite directions and are worth measuring locally: retrieval-side predictor accuracy *declines* as k grows (2→10) while post-generation answer perplexity *improves* with k [85]. A related caution: semantic entropy — entropy over meaning-equivalence clusters — is the right form of model-side uncertainty for free-form QA in the closed-book setting [88], but its advantage narrows once retrieval is in the loop, where it is outperformed by both p(True) and the single-pass passage-utility predictor while costing N generations per query [86]. **Moderate.**

A finding that constrains the architecture rather than the features: **injecting retrieved context suppresses the reader's own abstention regardless of sufficiency.** Measured abstention rates collapse from 100% → 18.6% (Gemini 1.5 Pro), 84.1% → 52% (Claude 3.5 Sonnet) and 34.4% → 31.2% (GPT-4o) when RAG context is added, and given *sufficient* context models still hallucinate more often than they abstain across all three datasets tested [87]; "negative rejection" is among the weakest of four measured RAG abilities on RGB [89]; and on CRAG, straightforward RAG lifts accuracy only from ≤34% to 44%, with the best industry solutions answering 63% without hallucination [90]. **Moderate to strong.** The abstention decision must therefore live *outside* the generator — prompting the reader to say "I don't know if the context is insufficient" is measurably undermined by the act of supplying context.

Retrieval-side thresholds are fitted parameters, not constants. QPP methods' relative prediction quality flips depending on which of several equivalent query formulations represents the same information need [91]; QPP quality drops statistically significantly on neural retrievers versus bag-of-words — by as much as 10% on passage retrieval — and fails hardest on exactly the queries where neural rankers differ most from lexical ones [92]; and correlation-based point-estimate evaluation of QPP is itself statistically unsound and should be modelled as a distribution [93]. **Strong.** Any threshold needs re-calibration per retriever, per corpus, per k, with a regression test that fires when the operating point drifts.

Retrieval *relevance* is also not answer utility. The retriever's highest-scoring documents that are not directly relevant actively hurt LLM accuracy, while adding **random** documents improved accuracy by up to 35% [94]; position in the assembled context can dominate relevance [10]; query variants maximising nDCG often fail to produce the best generated answers [95]; and a retrieval signal deliberately aligned with answer support "does not robustly predict answer quality on unseen topics" [96]. **Strong** for the first two, **weak** (2026 preprints, **[unverified pass]**) for the last two. Never use nDCG or recall@k as the proxy target for an answerability gate; train on end-task correctness.

On **staleness metadata** specifically — the third retrieval-side signal in the design question — the evidence is indirect and there is a real gap. Outdated content in the corpus degrades RAG two ways: it distracts the model from correct information *and* misleads it into potentially harmful outputs **even when current information is also available** [97] (**moderate**, 2025 preprint benchmark, **[unverified pass]**); CRAG shows accuracy markedly lower for facts with higher temporal dynamism [90]; SituatedQA finds ~16.5% of NQ-Open questions have temporally or geographically context-dependent answers, with models trained on past data dropping ~15 points on present-day questions *even with an updated evidence corpus* [98]; and time-aware training improves calibration on facts from future periods [99]. Conversely a model's *claimed* knowledge cutoff is unreliable — measured "effective cutoffs often differ from reported cutoffs" [100] — so freshness must be a document-level attribute you own and can audit, never something the reader arbitrates from priors. **But no study isolates staleness metadata as a feature and reports its incremental AUROC once retrieval-sufficiency and model-confidence features are already in the model.** That is an open question, not a supported claim.

Two structural points close the loop with the provenance section. First, permissions and validity intervals must be enforced *inside* query processing, not as post-filters: Büttcher & Clarke show constructively that with a system-wide index, BM25 ranking over global statistics and post-filtering, an unprivileged user can create a few files containing novel terms, read back the scores, solve algebraically for |F| and avgdl, and recover the exact document frequency of any term including in unreadable files — and that query-integration is also *faster* when the visible fraction is small, "because relevance scores for fewer documents have to be computed" [101]. **Strong** (USENIX FAST 2005, constructive attack plus evaluation). Whether this transfers to dense vector retrieval is **unresolved**: the attack depends on collection-level terms in the score, and while ANN index structure, score normalisation, MMR diversification and hybrid BM25 components all reintroduce corpus dependence, no published study measures leakage from permission-post-filtered vector search. Second, filtered retrieval is not free: filter-unaware ANN indices give "high search latency or low recall" on filtered queries [102], predicate-subgraph traversal over HNSW yields 2–1,000× higher throughput at fixed recall versus prior hybrid methods [103], and policy-aware vector search is framed as an open three-way tension between policy correctness, recall and latency with no published quantification of pre-filter vs post-filter vs partitioned-index trade-offs [104]. **Strong** for the systems results, **weak** for the policy framing. ACLs and validity intervals are index-native schema decisions made *before* the index exists.

Finally, two framings worth adopting wholesale. Model the system as **two gates, not one** — retrieve-or-not and answer-or-abstain — since they share features but have different targets and costs: retrieval-augmented LMs outperform much larger unassisted models on low-popularity entities while unassisted models stay competitive on high-popularity ones, and retrieving only when necessary improves performance *and* reduces cost [105][106][83]. **Moderate.** And adopt an **asymmetric primary KPI** (wrong ≪ abstain < correct) from day one, with "knowledge-gap canaries" — questions whose answers are verifiably absent from your corpus — as a standing regression suite: CRAG operationalises the scoring (+1 / −1 / 0) [90], the argued diagnosis is that benchmarks scoring abstention like a wrong answer create pressure toward guessing [107], and a penalty-aware audit of three commercial RAG products found accuracy-when-answering clustered at 97.0–98.0% while canary-violation rates differed roughly sixfold (16.7% vs 98.1%) — conventional accuracy discriminated almost nothing about the property that matters [108]. **Moderate**, and the audit is a 2026 industry preprint **[unverified pass]**.

Conformal prediction does not rescue any of this at the individual level. Exact conditional coverage is provably impossible in a distribution-free setting [109]; RAG-specific conformal frameworks inherit marginal-only coverage; and one recent system explicitly reports that after conformal chunk selection "the associated statistical guarantees do not hold generally, since the assumption of sample exchangeability depends on the retriever setup", shipping diagnostics for whether a setup qualifies [110]. **Strong.** A "90% guarantee" is a population average that protects no particular tenant, topic, jurisdiction or freshness stratum — and the calibration-sample cost of per-segment risk control is uncharacterised.

### What the evidence does not support

**"A big enough context window makes a memory system unnecessary."** Refuted for unbounded histories by a within-model ablation: the *same* model loses 30.3% (GPT-4o) to 55.1% (Llama-3.1-70B) relative accuracy when given a full 115k-token history rather than just the evidence sessions [1], reproduced independently at ~80% → ~55% for Claude Sonnet 4 [2]. But the claim is largely *correct* for bounded corpora that fit: long context beats RAG on average when sufficiently resourced [3] and rivals dedicated retrieval pipelines on LOFT [5]. The real variable is corpus boundedness, not window size.

**"Lost in the middle is a live constraint — put important content at the start or end."** Largely obsolete as stated. LongPiBench, over five commercial and six open-source models, reports that "most current models are robust against the 'lost in the middle' issue"; the bias that survives is driven by the *distance between* multiple relevant pieces, not absolute position [9]. The original TACL finding was real for its model generation [10]. This one is **contested** rather than settled — the counter-evidence is one benchmark, and the mitigation is cheap — but it should not be cited as current fact.

**"A model that scores well on needle-in-a-haystack can use its full advertised context window."** Contradicted three ways: most long-context models achieve perfect NIAH while showing large downstream gaps, and HELMET's own categories correlate poorly with each other [6]; only about half of models claiming ≥32K maintain satisfactory performance at 32K [7]; and stripping lexical overlap between question and needle drops 11 of 13 models claiming 128K+ below half their short-context baseline at 32K, GPT-4o from 99.3% to 69.7% [8]. NIAH is a lexical-match task that rewards the shortcut it fails to test.

**"Commercial memory layers substantially outperform plain retrieval."** An independent reproducible LOCOMO testbed found mem0, plain RAG and full-context all clustered at 77–81% with Graphiti and cognee at 55–56% — inverting the vendor ordering — and plain RAG matching the top cluster at **8.4× lower total cost of ownership** than mem0 [16]. Separately, Letta reported being unable to reproduce Mem0's MemGPT baseline (Mem0 did not respond to requests for clarification or supply the modified implementation) and measured 74.0% where Mem0 reported 68.5% [18][17].

**"Memory systems save >90% of token cost versus resubmitting the conversation."** Conditional at best. An independent serving-cost study found the break-even point ranges "from the first tens of turns for the cheapest to never within 400 turns for the most expensive", that the backbone drives cost as much as the memory system does, and that serving cost cannot be predicted from conversation length and message size alone [15][17]. Write-side extraction and consolidation calls — which scale with ingestion, not queries — are the cost vendor figures omit.

**"MemGPT / virtual context management is an established, peer-reviewed result."** It is an arXiv preprint (v2, February 2024) with no peer-reviewed venue despite ~1,195 citations, and its evaluation used Deep Memory Retrieval, a benchmark defined by the same team and now near-saturated (a competitor reports 94.8% against MemGPT's 93.4%) [11][12]. Cite the idea; do not cite the result as established.

**"LOCOMO scores are comparable across papers, so you can rank systems from published numbers."** Independent evaluations place memory systems at 21–54% where system papers self-report 68–99% on the same benchmark; six unreported protocol variables move rankings, and one convincing win vanished once retrieval budget was equalised — the winner had been pulling 2.6M characters per query [15][14]. Token-F1 and LLM-as-judge differ by 27.5 points on identical outputs [19], and changing only the credited scoring target moves nDCG on 83.4–94.0% of queries without rerunning retrieval [20].

**"Structuring memory as a knowledge graph or formal ontology improves answer quality."** Converging evidence against from four directions: organisation roughly halves retrieval cost but "no agent we measure converts organization itself into better answers" [22]; earlier KG-structured RAG "drops considerably below standard RAG" on basic factual memory [23]; GraphRAG's headline is LLM-judged comprehensiveness/diversity win-rates on global sensemaking with no retrieval-accuracy comparison reported [24]; and the independent LOCOMO testbed ranks both graph systems last, attributing the gap to retrieval incompleteness [16][25]. Structure is defensible on cost, latency and auditability. The accuracy case is not made.

**"Expire memories by recency; decay them with time."** Recency was the *worst* retention signal in the one head-to-head comparison available: 0.368 gold-evidence retention against 0.770 for a learned multi-factor model, 0.657 uniform and 0.518 for the best single factor, with reliability and self/user relevance dominating the learned weights and query-time goal similarity correctly down-weighted [27]; a separate study observed purely time-driven decay collapsing to near-zero weights over 100 rounds [28]. Both are unreplicated preprints from an unverified review pass — the claim they refute is popular and the refutation is thin, so treat this as "the obvious default is unsupported", not "the opposite is proven".

**"The Generative Agents retrieval score (recency + importance + relevance) is a validated design."** It was validated against human ratings of the *believability* of simulated agent behaviour in a sandbox, with an ablation showing observation, planning and reflection each contribute to believability [111]. There is no evaluation of factual retrieval accuracy in that work. Combined with the recency result above, the formula's most-copied term is the one with the worst independent evidence.

**"LLM-as-a-judge is an acceptable objective metric for memory-system accuracy."** The ~80% judge-human agreement figure was measured on *chatbot response preference*, not factual memory recall, and the same paper documents position, verbosity and self-enhancement biases [21]. On memory benchmarks specifically, judge and token-F1 diverge by 27.5 points on identical outputs [19] and judge choice is one of the protocol variables shown to move rankings [14]. **Provenance failure: no study validating judge-human agreement on an agent-memory benchmark was found.** Every published memory-system number rests on a metric that has not been validated for the task it is being used on.

**"Adding retrieval grounds the model, so it can only help."** On RAGuard, whose misleading documents are naturally occurring rather than synthetically injected, *every* tested RAG system performed worse than its own zero-shot no-retrieval baseline while human annotators did better; the authors argue that benchmarks using gold documents or synthetic noise systematically overestimate RAG performance [31]. Broader retrieval is also not uniformly safer — it improves long-context factual QA while *degrading* sequential decision-making by diverting attention from action-critical information [29].

**"RAG makes models more willing to say 'I don't know'."** Contradicted. Adding retrieved context collapses abstention: Gemini 1.5 Pro 100% → 18.6%, Claude 3.5 Sonnet 84.1% → 52%; and with *sufficient* context models still hallucinate more often than they abstain [87]. "Negative rejection" is among the weakest of four measured RAG abilities on RGB [89], and CRAG lifts straightforward-RAG accuracy only from ≤34% to 44% [90].

**"Frontier models know when to say 'I don't know'."** Larger, higher-baseline models "excel at answering queries when the context is sufficient, but often output incorrect answers instead of abstaining when the context is not" [87]; GPT-4o-class models adopt incorrect retrieved content over their own correct prior more than 60% of the time, and the *less* confident the model is in its prior, the *more* likely it is to adopt the retrieved content [112]; SelfAware reports a "considerable gap between the capabilities of these models and human proficiency in recognizing the limits of their knowledge" across 20 LLMs [113].

**"LLMs are badly calibrated."** Over-broad as stated. Large models are well calibrated on multiple-choice and true/false questions "when they are provided in the right format" [114]; pre-trained GPT-4 is described by its own technical report as "highly calibrated" on MMLU [115]; BERT/RoBERTa are calibrated in-domain [116]; and the decay-with-size and decay-with-shift trends were revisited, with the most recent non-convolutional image models among the best calibrated [117]. Miscalibration is regime-specific — free-form generation, out-of-distribution inputs, post-RLHF models — and heavily format-dependent. The ECE numbers underpinning much of this literature are themselves biased downward [76].

**"RLHF destroys calibration." — Provenance failure.** This traces almost entirely to Figure 8 of the OpenAI GPT-4 Technical Report: "the pre-trained model is highly calibrated... after the post-training process, the calibration is reduced" [115]. That is one vendor figure, one model, one multiple-choice benchmark (a subset of MMLU), with no disclosed methodology, no error bars and no released data. No peer-reviewed multi-model replication was found. The nearest independent support is indirect — for RLHF-fine-tuned models, verbalized confidences are typically better calibrated than conditional probabilities [118] — which is consistent with, but does not establish, the general law. Treat it as an unreplicated vendor observation, not a design premise.

**"Just ask the model for a confidence number."** Contested. A fine-tuned GPT-3 can emit well-calibrated verbalized probabilities [119], and verbalized confidences beat conditional probabilities for RLHF'd models [118] — but a systematic evaluation of confidence elicitation found LLMs verbalizing confidence "tend to be overconfident, potentially imitating human patterns" [120]. Use it as one candidate feature in a trained combiner, never as a probability you threshold directly.

**"A retrieval similarity score threshold tells you whether the corpus can answer the question."** Contradicted quantitatively: score-distribution predictors (NQC/score separability, WIG, SMV) correlate ~0.1–0.2 with actual RAG gain and pre-retrieval predictors ~0–0.1, against 0.35–0.55 for model uncertainty and 0.71–0.89 for joint predictors [83]; QPP-only prediction of answer quality tops out around ρ ≈ 0.25 [85]. The thresholds also do not transfer across retrievers, query formulations or k [92][91][93].

**"Retrieval-side signals are inherently more trustworthy than model confidence because they are grounded."** Half-true, and the useful distinction is *supervision*, not side. Raw retrieval statistics are weak; learned retrieval-side scorers are strong (AUROC 0.78–0.81, beating p(True) and semantic entropy, especially on unanswerable questions) [86]; but retrieval-side accuracy declines as context grows while model-side post-generation perplexity improves [85], the strongest predictors in every study are *joint* [83], and abstaining on a retrieval-sufficiency signal alone measurably lowers overall performance [87]. **Provenance failure: the comparison is confounded — every strong retrieval-side result is supervised on end-task correctness while the model-side baselines it beats are unsupervised, and no matched-supervision ablation exists.**

**"Better retrieval (higher nDCG/recall) means better answers."** Contradicted. The retriever's highest-scoring documents that are not directly relevant negatively impact the LLM, while adding *random* documents improved accuracy by up to 35% [94]; position in the assembled context can matter more than relevance [10]; query variants maximising nDCG often fail to produce the best answers [95]; and an answer-support-aligned retrieval signal still "does not robustly predict answer quality on unseen topics" [96].

**"AUROC is the metric for evaluating an abstention signal."** Contradicted. A systematic re-evaluation of failure detection under a holistic risk-coverage view found many published gains to be evaluation artifacts and "a simple softmax response baseline" to be the overall best performing method, which the authors describe as underlining "the drastic shortcomings of current evaluation" [75]. Report AURC and coverage-at-target-risk alongside a max-score baseline.

**"Abstention is safe — the worst case is answering fewer questions."** Contradicted twice over. Selective classification can *magnify* accuracy disparities between groups, and increasing abstention can *decrease* accuracy on some groups outright, observed across five vision and NLP datasets with a proof of when it happens [77]. And over-abstention is a real regression: XSTest documents systematic exaggerated refusal of clearly safe prompts that merely resemble unsafe ones [78].

**"SQuAD 2.0 measures whether a system knows what it doesn't know, so a good score transfers."** Contradicted. A top SQuAD 2.0-trained system "drops considerably in out-of-domain scenarios", failing even on the simpler non-competitive IDK questions [80]; SQuAD 2.0 contains artifacts MRC models demonstrably learn [81]; and under domain shift softmax-based abstention fares poorly because models are overconfident out of distribution [82].

**"Conformal prediction gives a per-answer correctness guarantee."** Contradicted. Conformal methods provide *marginal* coverage, and exact conditional coverage is provably impossible without distributional assumptions [109]; RAG-specific frameworks inherit this, and the exchangeability assumption "depends on the retriever setup" and can simply fail, which one recent system acknowledges by shipping diagnostics for whether a given setup qualifies [110].

**"W3C PROV is *the* provenance standard, so adopt PROV-O."** Not supported as a *serialisation* choice, and the counter-evidence includes W3C's own census: of 66 reported implementations only three both produced and consumed all PROV-DM constructs, and only three validators implemented all of PROV-CONSTRAINTS [37]. The largest 2020s deployments avoid it — a direct token count over the C2PA 2.1 specification finds **zero** occurrences of "PROV-O", "prov-dm", "W3C PROV" or "RDF" while it normatively cites Dublin Core and references schema.org, XMP, Exif and IPTC [39]; OpenLineage defines its own Job/Run/Dataset+facets JSON model [40]; FHIR ships a bespoke resource "based on" PROV that covers only Generation-of-Entity [41]; RO-Crate chose schema.org in JSON-LD and permits a PROV bundle only as a side-file [42]. PROV's *concepts* are widely reused; PROV-O as a wire format is not.

**"PROV-O is cheap to adopt — it's just a vocabulary, you add some triples."** The half that carries the interesting information is expensive by construction: qualifying one influence relation goes from 2 triples to 5 triples plus a new node *before* any domain property attaches, and 20 of ~30 classes and 20 of ~46 properties exist solely to support that pattern [35]. Emitting PROV from application code was hard enough to motivate a whole templating system published in IEEE TSE, splitting topology from values, with bindings ~40% the size of the provenance they expand into [38].

**"Define a richer vocabulary and richer data will follow."** Directly contradicted at web scale. Bulk-integrating a large medical vocabulary into schema.org produced a domain "for which no deployed data can be found at all"; the official extension mechanism is "only rarely used, without a measurable impact"; and `schema:sameAs` — the property that makes the corpus linkable — is "deployed by less than 0.02% of all Microdata providers" [46]. Web Data Commons shows four to five orders of magnitude between head and tail classes inside one vocabulary of 823 types [45][44]. Dublin Core repeats it: only `title` and `identifier` reach 100% of repositories; `creator` appears in 39% of records [49]. Deprecations propagate quickly; additions do not.

**"Future-proof the vocabulary by making it openly extensible."** Both a young and a mature standard converge the other way. schema.org's official extension mechanism went essentially unused, with no measurable impact of extension classes later becoming standard [46]; C2PA 2.x actively *tightened*, removing the deprecated Exif, IPTC and schema.org metadata assertions, replacing them with one general metadata assertion where "c2pa.metadata only allows a fixed set of schemas & values" [39]. What drove schema.org adoption was business incentive, copy-pasteable examples, embedding the writer in widely deployed tools, and legalising observed violations after the fact — not extensibility.

**"An answer with citations is a verifiable answer."** Two independent human audits of production systems, two years apart, say otherwise: "a mere 51.5% of generated sentences are fully supported by citations and only 74.5% of citations support their associated sentence" [59]; and ~25–30% of statements unsupported by listed sources, under half of Perplexity's citations pointing to a supporting source, 36% uncited sources for Bing, and at least 30% of listed sources supporting no unique information [60]. Users treat presence of a citation as the verification — "I'll just see that there is a source. That's it. I don't verify it." RAGTruth exists precisely because RAG systems "may still present unsupported or contradictory claims to the retrieved contents" [61].

**"Attribution measures whether the answer is true."** Explicitly denied by the framework that defines attribution. AIS is source-relative — whether "According to P, s" holds at time t — and its authors state that source characteristics "such as source quality... are out of scope in this work" and that "AIS does not set policy about where model output should fall" [62]. A system can be perfectly attributable and entirely wrong.

**"An NLI model or LLM judge can gate citation correctness per answer."** Not at the per-example level. ALCE's own TRUE-NLI judge agrees with humans at κ = 0.698 on citation recall and only 0.525 on precision [63]; AttributionBench's fine-tuned GPT-3.5 reaches only ~80% macro-F1 on the binary formulation [64]; SummEdits finds most LLMs "close to random chance" on inconsistency detection with GPT-4 8% below humans [65]. And the middle state is unmeasurable: "there is no existing model that can judge whether a citation partially supports a claim" [63], with a dedicated comparative study finding "no single metric consistently excels" [66].

**"High citation precision/recall indicates a good cited-answer system."** The metric has a degenerate optimum: emitting the top-1 retrieved passage verbatim scores 99.4 citation recall and 99.4 precision on ASQA against 73.6 / 63.0 for a real generated answer, while MAUVE fluency collapses from 66.6 to 20.8 [63]. Citation quality reported alone is maximised by copying.

**"Human annotation is the reliable ground truth for attribution, so scale it with more annotators."** Only for short sources, and it is expensive. AIS inter-annotator agreement runs from Krippendorff's α = 0.91 on conversational QA to 0.60 (Wizard-of-Wikipedia) and 0.46 (CNN/DM summarization), attributed by the authors to how much context an annotator must read, at 73–308 seconds per item after training [62]. More annotators does not fix disagreement caused by source length; a smaller cited unit does.

**"Broken citations are a link-rot problem — check for 404s."** Content drift dominates and archive coverage cannot be assumed: "the number of articles infected with reference rot is very close to the number of articles that lack appropriate Mementos", with only 22% of references having an archive snapshot within 30 days of publication and 0.3% within one day [54]. A URL returning 200 may no longer contain the text that supported the claim.

**"Resolving a conflict means picking the right value and deleting the wrong one."** The largest production knowledge base handling conflict at scale does the opposite: Wikidata's "deprecated" rank is retention-with-a-marker, kept to prevent accidental re-addition and to document how knowledge evolved, with queries excluding it by default; and rank is kept orthogonal to sourcing — "References merely state where a data value comes from; ranks indicate what data value is considered the most correct" [56].

**"Give the model both conflicting sources with good provenance metadata and it will weigh them correctly."** Model behaviour under conflict is driven by rhetorical coherence and agreement with pretraining, not by stored metadata: LLMs are "highly receptive to external evidence even when that conflicts with their parametric memory, given that the external evidence is coherent and convincing", yet show "a strong confirmation bias when the external evidence contains some information that is consistent with their parametric memory" [121]; over-reliance on memorised information is measured directly [122][123]. Presentation order of conflicting evidence flips 11.4–25.2% of predictions across six open-weight models [124] (**moderate**, one biomedical domain, open-weight models only). Provenance stored beside the context does nothing; conflict must be stated *in* the context. Explicit surfacing does pay — multi-agent debate over conflicting evidence improves RAMDocs/AmbigDocs by up to 15.80 points absolute — but the underlying benchmark still yields only 32.60 exact match for a strong RAG baseline, and the gap widens as evidence imbalance grows [125].

**"Probabilistic belief updating is the right way to handle conflicting memories."** It provides minimal advantage over plain last-write-wins on ordinary conversational recall, because standard benchmarks contain almost no contradictory, differently-reliable evidence; what did matter in the same study is that grounding trust in *source provenance* resists volumetric poisoning while grounding it in the statement's textual confidence does not [19]. Single-author, unreplicated, from an unverified review pass — but it reports against its own thesis.

**"Enforcing permissions at query time is sufficient — filter the retrieval results by the caller's ACL."** Necessary but not sufficient, for two independent reasons. Consolidating interaction history into reusable facts erased source constraints in 48 of 49 configurations across seven consolidators and seven backbones, after which there is no metadata left for a query-time filter to act on; persisting authority labels through consolidation cut unauthorised actions from 16.9% to 0.0% [32]. And post-filtering a ranked list is itself an exploitable leak wherever ranking uses corpus statistics — an unprivileged user can recover the exact document frequency of any term in files they cannot read — while query-integration is also faster when the visible fraction is small [101].

**"Prompt-level guardrails and output filtering are adequate permission enforcement."** Microsoft Research, reporting from a shipped Copilot Tuning deployment, argues these defences "are fundamentally probabilistic and fail to offer robust protection", and that the required invariant is deterministic and participant-aware: content must be authorised for *all* users in the interaction — the **intersection** of participants' permissions, not the union [126]. GateMem separately finds retrieval and external-memory methods still leaking unauthorised and explicitly deleted content [33].

**"Permission and freshness filtering is a cheap post-processing step over search results."** Contradicted on security [101] and on performance: filter-unaware ANN indices show "high search latency or low recall" on filtered queries [102], prior hybrid-search methods either perform poorly or support only restricted predicates [103], and post-filtering an ANN result set forces over-fetching, so the cheap option is not cheap.

**Provenance failure — claims with no primary source behind them.** Four in this area deserve naming. (1) *No study measures which PROV-O terms are actually used across a corpus of published PROV documents* — there is no PROV equivalent of the Web Data Commons per-class analysis; the W3C implementation report's "3 of 66" is the closest proxy and it counts implementations, not emitted data [37]. (2) *No neutral adoption census compares OpenLineage against Apache Atlas, DataHub, Egeria or PROV* — each project publishes its own integration list, so relative deployment claims are unsupported. (3) *The canonical statement of schema.org's design philosophy (Guha, Brickley & Macbeth, ACM Queue / CACM 2016) was not retrievable* during the source review — ACM returned 403 on both the Queue page and the OA gateway — so its widely-quoted adoption figures are unverified here and no numeric claim is made from it [127]. (4) *No membership-inference study, pre/post-cutoff comparison or canary analysis exists for LOCOMO*, so **the popular assertion that LOCOMO is contaminated is itself unsupported** — what is supportable is only that a benchmark public since 2024 being compared against models trained later is an uncontrolled variable, which is exactly what most memory-system comparison tables do [128][13]. One further disclosure worth recording as a base rate: at least one memory system paper disclosed post-hoc that source-specific phrases had leaked into its own query-expansion rules, rendering its reported retrieval scores "descriptive development measurements, not independent confirmation", and a third-party analysis attributed a competing system's headline retrieval performance primarily to the default embedding model of its underlying vector store rather than to its architectural contribution [129][14].
